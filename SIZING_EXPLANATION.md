# Engine-authored sizing explanations

Each priced variant now carries a `SizingTrace` from the actual sizing branch.
This is additive provenance, not a second sizing engine. All money is stored in
full base-currency units; the pack supplies the pair's actual currency when
rendering. No thousands/millions/billions scaling is applied to stored amounts.

## Fixed-loss method

The trace records the input loss budget, per-unit sizing proxy, requested
pre-cap notional, cap, final notional and determining rule:

- Positive proxy: loss budget / proxy, subject to the existing cap.
- Net credit: existing policy fixes notional at 10 times reference capital;
  it is not described as budget division.
- Missing/near-zero proxy: existing policy uses the cap. This is explicitly not
  a claim that the trade has no risk.

Ranked packs also record the original budget derivation: reference capital times
the reference distance, where distance is the target move from forward divided by
the input R:R. That input is not the net target-return ratio and does not assume
an executed stop. Custom trades inherit the active pack's budget provenance.

## Kelly method

The trace records the supplied distribution fingerprint/point count, bankroll,
full-Kelly notional fraction, lambda, pre-cap notional, cap and final notional.
Bankroll and cap reference capital are kept distinct even when the UI supplies
the same number for both. The distribution is the existing PM input; no
distribution is generated by this explanation layer.

Requested and effective methods remain separate. Missing-distribution fallback
is unchanged and explicitly recorded. A per-variant calculation failure remains
unsized with an error status; it does not silently become fixed-loss sizing.
Valid zero allocation, missing inputs and errors have distinct statuses.

## Agent behaviour and validation

All recommendation and custom-trade render paths include `SIZING AUDIT` text.
The agent explains the recorded inputs, branch and final amount without doing
arithmetic or presenting the sizing proxy as contractual maximum loss.

Pricing, scoring, rankings, optimisation, caps and fallback policy are unchanged.
Tests cover each sizing branch, Kelly/zero/error states, missing inputs, budget
provenance, custom-trade fallback and 1,000/1m/1bn currency formatting.
